    2. Replace the current `startObserving()` body with a pull-before-observe flow. Keep `flatMapLatest` or an equivalent cancellation boundary around the entire hydration and debounce chain. Preferred shape:
    ```kotlin
    @OptIn(ExperimentalCoroutinesApi::class, FlowPreview::class)
    fun startObserving() {
        if (observerJob != null) return
        observerJob = scope.launch {
            profileManager.activeProfileId
                .distinctUntilChanged()
                .flatMapLatest { profileId ->
                    flow {
                        val pullResult = pullBlobForProfile(profileId)
                        if (pullResult.isFailure) {
                            Log.w(TAG, "Skipping settings observer push for profile $profileId because hydration failed", pullResult.exceptionOrNull())
                            return@flow
                        }
                        emitAll(
                            observeProfileSettings(profileId)
                                .drop(1)
                                .debounce(2000)
                                .map { profileId }
                        )
                    }
                }
                .collect { profileId ->
                    if (applyingRemoteBlob) return@collect
                    pushBlobForProfile(profileId)
                }
        }
    }
    ```

    This satisfies D-01 by keeping the 2s debounce and profile-switch cancellation, and it closes the verifier gap by requiring a successful pull for the selected profile before pushes are enabled.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase RPC -> local DataStore | Remote profile settings JSON is parsed and applied to profile-scoped local DataStore preferences |
| Profile switch event -> Supabase RPC | Local active-profile changes trigger remote pull before local push observation begins |
| DataStore observer -> Supabase RPC | Local preference changes after debounce push a full v8 blob to Supabase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-14 | Tampering | `importSettingsBlob()` | mitigate | Normalize remote blobs to the known `syncedFeatures` allowlist, ignore unknown feature keys, clear each feature before apply so stale local keys cannot be pushed back upstream |
| T-04-15 | Denial of Service | `startObserving()` profile-switch hydration | mitigate | Keep `flatMapLatest` cancellation around pull/debounce work so rapid profile switches cancel obsolete work instead of piling up observers |

| T-04-17 | Tampering | Echo push after pull | mitigate | Preserve `applyingRemoteBlob`, `skipNextPushSignature`, and `syncMutex`; sign the normalized imported blob so observer emissions from a pull are skipped instead of re-pushed |
| T-04-18 | Spoofing | Profile ID during pull/push | mitigate | Continue using `ProfileManager.activeProfileId` and `pullBlobForProfile(profileId)`/`pushBlobForProfile(profileId)` through authenticated Supabase RPCs; do not add UI or caller-provided profile ID inputs |
