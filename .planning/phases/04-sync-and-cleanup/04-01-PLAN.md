private suspend fun <T> withJwtRefreshRetry(block: suspend () -> T): T {
    return try { block() } catch (e: Exception) {
        if (e.message?.contains("JWT") == true || e.message?.contains("401") == true) {
            authManager.refreshSession()
            block()
        } else throw e
    }
}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> Supabase RPC | Profile metadata pushed/pulled via authenticated RPCs; JWT required |
| Supabase RPC -> DB | Server-side function validates user_id from JWT before reading/writing profiles |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | ProfileSyncService push | mitigate | All RPCs use `withJwtRefreshRetry` — Supabase validates JWT and extracts user_id server-side; client never sends user_id in payload |
| T-04-02 | Tampering | SupabaseProfile pull | mitigate | `replaceAllProfiles()` only called when pull returns non-empty list; empty response = no-op. Profile IDs clamped to 1-4 by ProfileManager constraints |
| T-04-03 | Information Disclosure | SharedPreferences files | accept | SP files are in app-private `shared_prefs/` directory; Android sandboxing prevents cross-app access. File naming with `_p{id}` is not sensitive |
| T-04-04 | Elevation of Privilege | profilePrefsName() | mitigate | `profileManager.activeProfileId` is the single source of truth; no client-provided profileId parameter in the SP naming path |
</threat_model>
