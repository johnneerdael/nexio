<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Android broadcast -> receiver | External/system intents can reach manifest receivers if exported incorrectly |
| Receiver -> snapshot service | Broadcasts trigger provider refresh and scheduling work |
| Scheduler -> AlarmManager | PendingIntent action controls future app wakeups |
| Refresh failure -> retry diagnostics | Errors are logged for debugging |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-13 | Spoofing / Denial of Service | `ContinueWatchingAirAlarmReceiver` | mitigate | Declare receiver `android:exported="false"` and use package-scoped explicit `PendingIntent` with `setPackage(context.packageName)` |
| T-08-14 | Denial of Service | `ContinueWatchingSnapshotService.scheduleReemitIfNeeded` | mitigate | Schedule only the soonest withheld instant and keep the existing idempotency guard to prevent alarm churn |
| T-08-15 | Information Disclosure | Scheduler and refresh failure logs | mitigate | Log reason code, retry interval, and trigger time only; no TVDB credentials, tokens, raw API payloads, or auth headers |
| T-08-16 | Tampering | Alarm trigger behavior | mitigate | Receiver calls `ensureFresh(force = true)` and never directly reveals `scheduledReemit` rows |
</threat_model>
