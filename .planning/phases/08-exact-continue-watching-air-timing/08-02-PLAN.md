<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tracking provider next-up -> TVDB router | Provider content IDs and season/episode coordinates are used for TVDB lookups |
| TVDB router -> TrackingNextUpEntry | Remote metadata controls timing fields consumed by the gate |
| Enricher logs -> debug output | Failures are recorded for diagnostics |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | Tampering | `TvdbContinueWatchingTimingEnricher` | mitigate | Preserve provider IDs and only copy TVDB availability fields; do not change season/episode/video identity from TVDB timing enrichment |
| T-08-06 | Denial of Service | `TvdbContinueWatchingTimingEnricher.enrich` | mitigate | Catch exceptions per entry so malformed TVDB metadata or one failed lookup cannot break the whole Continue Watching flow |
| T-08-07 | Information Disclosure | Enricher diagnostics/logging | mitigate | Log only reason code and contentId; never log TVDB API key, PIN, bearer token, raw auth header, or raw response body |
| T-08-08 | Repudiation | Provider fallback path | mitigate | Route through `TvMetadataRouter` so TVDB inactive/fallback/skipped-TMDB events remain centralized from Phase 7 |
</threat_model>
