Use this control flow:
```kotlin
val response = runCatching {
    tvdbApi.getSeriesEpisodes(
        authorization = authorization,
        id = identity.tvdbId,
        seasonType = DEFAULT_SEASON_TYPE,
        page = 0,
        season = seasonNumber
    )
}.onFailure { error ->
    Log.w(TAG, "TVDB season metadata request failed reason=${error.javaClass.simpleName}")
}.getOrNull() ?: return@withContext emptyList()

if (!response.isSuccessful) {
    Log.w(TAG, "TVDB season metadata request failed status=${response.code()}")
    return@withContext emptyList()
}

val records = response.body()?.data.orEmpty()
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TVDB router -> TMDB fallback | Provider fallback crosses from TVDB-controlled TV routing into TMDB network/cache behavior |
| TVDB API -> TVDB season cache | Untrusted and fallible HTTP responses become local metadata cache entries only on successful responses |
| Settings store -> provider routing | User-disabled TMDB settings must be honored before fallback calls leave the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07-01 | Repudiation | `TvMetadataRouter` | mitigate | Preserve existing fallback diagnostics while adding a TMDB-active guard before every TMDB fallback helper |
| T-07-07-02 | Information Disclosure | `TvMetadataRouter` | mitigate | Do not log TMDB or TVDB API keys while reading settings or returning disabled-fallback decisions |
| T-07-07-03 | Tampering | `TvdbMetadataService.fetchSeasonEpisodes` | mitigate | Write TVDB season cache entries only after successful TVDB HTTP responses |
| T-07-07-04 | Denial of Service | `TvdbMetadataService.fetchSeasonEpisodes` | mitigate | Do not convert transient 401/429/5xx/exception failures into long-lived empty cache entries that suppress future successful fetches |
</threat_model>
