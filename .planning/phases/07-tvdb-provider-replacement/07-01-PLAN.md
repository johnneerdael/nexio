<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase 6 TVDB settings/auth -> Phase 7 provider code | Secret-backed API key/PIN and bearer-token state must be consumed without logging or reimplementing credentials |
| TVDB API data -> local cache/UI models | Untrusted provider data is mapped into cache and UI-facing metadata |
| Poster-ratings settings -> TVDB cache keys | Provider token affects poster output and must not include raw API keys |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Phase 6 prerequisite and diagnostics | mitigate | Do not read `.thetvdb.apikey`; do not log TVDB API key, PIN, bearer token, or login payload; use only provider-token hashes in cache keys |
| T-07-02 | Repudiation | `TvMetadataDiagnostics.kt` | mitigate | Define exact event names `tvdb_inactive_tmdb_fallback`, `tvdb_success`, `tvdb_fallback_tmdb`, `tmdb_tv_skipped`, and `poster_ratings_override` |
| T-07-03 | Tampering | `MetadataDiskCacheStore.kt` | mitigate | Use separate `tvdb::` and `tvdb_episode::` prefixes and TVDB schema-version fields instead of TMDB cache names |
| T-07-04 | Tampering | Phase 6 identity prerequisite | mitigate | Block if `TvdbIdentityService` or equivalent is absent so Phase 7 cannot route invalid IDs through TMDB before TVDB success-path routing |
</threat_model>
