<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings copy -> user provider expectations | Misleading copy can hide fallback or unexpected TMDB calls |
| Poster-ratings API key -> poster URL generation | API key appears in external poster URL output by design but must not enter diagnostics/cache secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Settings/tests | mitigate | Do not include TVDB API key/PIN/token in resources, tests, diagnostics, or fixtures |
| T-07-02 | Repudiation | Settings provider copy | mitigate | Copy explicitly states TVDB for TV, TMDB for movies/fallback, poster-ratings for supported posters |
| T-07-03 | Tampering | Poster URL precedence | mitigate | Tests assert TopPosters `tvdb:` URL output and RPDB IMDb-only fallback behavior |
| T-07-04 | Tampering | Settings routing assumptions | accept | This plan changes copy only; invalid ID routing is mitigated in `TvMetadataRouter` plans |
| T-07-05 | Repudiation | Fallback observability | transfer | This copy-only plan does not emit or change fallback telemetry; fallback observability is delegated to `TvMetadataRouter` and Home routing plans that emit `tvdb_fallback_tmdb` / `tmdb_tv_skipped` diagnostics |
| T-07-06 | Tampering | TVDB/TMDB cache namespace separation | transfer | This copy-only plan does not modify metadata cache code; namespace separation is delegated to Plan 01 cache work using `tvdb::` and `tvdb_episode::` prefixes |
</threat_model>
