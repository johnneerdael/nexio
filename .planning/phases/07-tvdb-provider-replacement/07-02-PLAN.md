Add public methods:
```kotlin
suspend fun fetchEnrichment(request: TvMetadataRequest): TvMetadataDecision<TvMetadataEnrichment>
suspend fun fetchEpisodeEnrichment(request: TvMetadataRequest): TvMetadataDecision<Map<Pair<Int, Int>, TvEpisodeMetadata>>
suspend fun fetchSeasonEpisodes(contentId: String, fallbackContentId: String?, seasonNumber: Int, language: String? = null): TvMetadataDecision<List<TvSeasonEpisode>>
```

Routing rules:
- If `request.contentType` is not `ContentType.SERIES` or `ContentType.TV`, call TMDB directly and return `TvProvider.TMDB`.
- For TV, read `TvdbSettingsDataStore.settings.first()` and treat TVDB active only when Phase 6 settings indicate enabled and configured.
- If inactive, call TMDB fallback and emit `TVDB_INACTIVE`.
- If active, call `tvdbIdentityService.resolveSeries(request.contentId, request.contentType)` before any TMDB lookup.
- If TVDB identity and TVDB metadata succeed, emit `TVDB_SUCCESS` and `TMDB_TV_SKIPPED`, return `TvProvider.TVDB`, and do not call `TmdbService.ensureTmdbId`.
- If identity or metadata is missing, emit the missing reason plus `TVDB_FALLBACK_TMDB`, then call TMDB fallback.

Add private adapter functions that convert `TmdbEnrichment`, `TmdbEpisodeEnrichment`, and `TmdbEpisode` into `TvMetadataEnrichment`, `TvEpisodeMetadata`, and `TvSeasonEpisode` for movie and fallback decisions. These adapters must set `seriesTvdbId = null`; do not derive a fake TVDB ID from TMDB IDs, content IDs, or fallback IDs. Keep `More Like This`, reviews, trailers, cast/company/network discovery, and reference taxonomy out of this router.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI/Home/Detail request -> `TvMetadataRouter` | Untrusted content IDs and content types decide provider routing |
| `TvMetadataRouter` -> Phase 6 identity service | Identity lookup must select a TVDB series before TVDB metadata calls |
| `TvMetadataRouter` -> TMDB fallback | Fallback is allowed only after observable TVDB inactive/missing/unavailable reasons |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | `TvdbMetadataService` | mitigate | Never log TVDB credentials, bearer tokens, or raw auth headers; tests must not contain API key/PIN fixtures |
| T-07-02 | Repudiation | `TvMetadataRouter` | mitigate | Emit exact diagnostics for inactive, success, fallback, and skipped TMDB TV calls; fallback tests assert event names |

| T-07-04 | Tampering | `TvMetadataRouter` ID handling | mitigate | Resolve TVDB series identity before TVDB calls and call `TmdbService.ensureTmdbId` only inside fallback branches |
</threat_model>
