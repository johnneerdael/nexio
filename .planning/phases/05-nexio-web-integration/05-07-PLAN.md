<objective>
Close the Phase 5 WEB-03 and WEB-04 settings-shape gaps by making nexio-web save profile settings in the Android v8 encoded per-feature blob contract while continuing to expose PortalSettings to the web UI.

Purpose: The verifier found that the web UI saves PortalSettings JSON, but Android profile settings sync imports only encoded v8 feature blobs. This plan adds a web adapter that merges catalog and formatter changes into the existing encoded blob, preserving unrelated Android preference keys, and adds Android regressions that import the resulting encoded data into real DataStores.
Output: Web adapter utility, wired profile settings GET/POST routes, web adapter tests, and Android DataStore import regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> nexio-web profile settings POST | Authenticated but user-controlled PortalSettings and changedPaths cross into server-side sync payload construction |
| nexio-web -> Supabase profile settings blob | Server route writes per-profile settings JSON consumed by Android |
| Supabase -> Android DataStore import | Remote JSON blob is parsed and applied to local per-profile settings stores |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07-01 | Tampering | `settings.post.ts` profileIndex and settings body | mitigate | Keep existing `validateProfileIndex`, require object settings payload, sanitize through `sanitizePortalSettings`, and merge only known WEB-03/WEB-04 paths into encoded keys |
| T-05-07-02 | Tampering | `changedPaths` supplied by browser | mitigate | Treat changedPaths only as an allowlist for known path mapping; ignore unknown paths and never use path strings as raw preference keys |
| T-05-07-03 | Denial of Service | Stored settings JSON parse/decode | mitigate | Catch malformed stored blobs in adapter and fall back to sanitized defaults rather than throwing from GET or writing malformed preference values |
| T-05-07-04 | Information Disclosure | Formatter custom template content | accept | Formatter templates are user-authored non-secret settings already synced to the user's TV profile; no secrets or OAuth tokens are included |
| T-05-07-05 | Elevation of Privilege | Cross-profile settings writes | mitigate | Continue using bearer token plus Supabase auth-scoped `sync_pull_profile_settings_blob` / `sync_push_profile_settings_blob` with validated profile index 1-4 |
</threat_model>
