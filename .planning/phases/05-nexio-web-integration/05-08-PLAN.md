<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase profiles.avatar_url -> Android profile persistence | Remote URL data enters local persisted profile JSON |
| Android profile persistence -> TV avatar UI | Stored URL is emitted to Compose avatar surfaces and loaded by Coil |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08-01 | Tampering | `ProfileJson.avatarUrl` | accept | The URL is already authenticated profile data from the Supabase profile row; this plan only preserves the existing field through local serialization |
| T-05-08-02 | Information Disclosure | Public avatar URL in local DataStore | accept | D-14 locked profile avatars to a public Supabase Storage bucket; storing the public URL locally matches the approved contract |
| T-05-08-03 | Denial of Service | Malformed legacy profile JSON | mitigate | Keep `avatarUrl` nullable with a default value so old JSON without `avatar_url` continues to parse; existing parse failure fallback remains unchanged |
| T-05-08-04 | Spoofing | Avatar UI display source | transfer | URL ownership and profile scoping are enforced by web upload routes and Supabase profile sync; Android persistence does not authenticate images |
</threat_model>
