<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> authenticated authorize-start POST | profileIndex is untrusted; route must require bearer token and validate ownership before returning provider authorizeUrl |
| Browser -> provider OAuth authorize URL | Only the signed opaque state and provider OAuth parameters may be placed in the URL; never include Supabase JWTs |
| OAuth provider -> callback GET | Provider redirects do not carry Supabase bearer headers; callback must verify signed state and recover trusted userId/profileIndex from it |
| OAuth provider -> callback route | code/state must be validated before token exchange |
| Nuxt server route -> Supabase service-role RPC | Service role writes profile tokens; user_id must come from supabaseUser(), never the client |
| Disconnect route -> provider revoke endpoint | Provider token revoke must happen before local token deletion per D-12 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-09 | Tampering | Per-profile auth token storage | mitigate | Server derives user id from `supabaseUser(event)`, validates `profileIndex` 1-4, and writes via `service_set_profile_auth_token` |
| T-05-10 | Information Disclosure | Auth status query | mitigate | `profile_auth_status` returns only masked metadata and never `token_payload` |
| T-05-11 | Spoofing | OAuth callback state | mitigate | Callback validates signed/opaque `state` with profileIndex and CSRF nonce before token exchange |
| T-05-11b | Spoofing | OAuth callback user binding | mitigate | authorize.post signs `user.id`, profileIndex, provider, nonce, and expiry after bearer-token auth; callback verifies the signature and uses the recovered userId for service-role token storage because provider redirects have no Supabase Authorization header |
| T-05-12 | Repudiation | Trakt/Simkl disconnect | mitigate | Trakt route calls `oauth/revoke` before deletion; Simkl route is blocked until an official revoke endpoint or explicit user decision is available |
</threat_model>
