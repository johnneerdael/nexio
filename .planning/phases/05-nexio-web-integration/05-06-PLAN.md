The `ProfileAuthToken` model must decode `token_payload` as JSON, not `Map<String, String>`:
```kotlin
@Serializable
data class ProfileAuthToken(
    @SerialName("profile_index") val profileIndex: Int,
    @SerialName("token_type") val tokenType: String,
    @SerialName("token_payload") val tokenPayload: JsonObject = buildJsonObject {},
    @SerialName("masked_preview") val maskedPreview: String = "",
    val source: String = "",
    val linked: Boolean = true,
    @SerialName("revoked_at") val revokedAt: String? = null,
    @SerialName("updated_at") val updatedAt: String = ""
)
```
Use `JsonObject`/`JsonElement` so numeric OAuth fields from Plan 03 decode safely.

`ProfileWebSyncService` should inject `Postgrest`, `TraktAuthDataStore`, and `SimklAuthDataStore`. Provide:
- `suspend fun syncActiveProfile(profileIndex: Int): Result<Unit>` that pulls `profile_auth_tokens` for `profileIndex`, compares remote `updated_at` with local last-linked timestamp when available, and writes newer Trakt/Simkl tokens to the per-profile auth stores.
- If a remote token row has `linked == false` or `revokedAt != null` and its `updated_at` is newer than the local last-linked timestamp, clear the corresponding local Trakt/Simkl auth store for that profile. This is the unlink propagation contract from Plans 05-01 and 05-03; row absence is not enough to indicate unlink.
- helper extraction methods using `tokenPayload["accessToken"]?.jsonPrimitive?.content` and `tokenPayload["refreshToken"]?.jsonPrimitive?.contentOrNull`.
- no broad `catch { emptyList() }` behavior that hides failures; return `Result.failure` when Postgrest token pull fails.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase -> Android app | Profile data and auth tokens pulled via Postgrest; RLS must scope rows to the authenticated user |
| Supabase Storage public URL -> Coil | Avatar URLs are public image URLs and must not contain secrets |
| Supabase JSON token payload -> DataStore | JSON payload can contain mixed value types; decoder must not assume strings-only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-18 | Spoofing | ProfileWebSyncService Postgrest queries | mitigate | Queries use authenticated Supabase client and table RLS filters by auth.uid() |
| T-05-19 | Information Disclosure | Avatar URL rendering | accept | Public bucket stores profile photos only, not tokens; token payload never rendered in UI |
| T-05-20 | Tampering | Token payload decoding | mitigate | Decode `token_payload` as `JsonObject`/`JsonElement` and extract only known token fields; numeric OAuth fields cannot crash string-map decoding |
| T-05-21 | Tampering | Startup/profile switch sync | mitigate | StartupSyncService invokes web-token sync at explicit launch/profile-switch integration points rather than leaving caller behavior implicit |
</threat_model>
