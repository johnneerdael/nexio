# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: nexio-web Integration.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Tech stack: Nuxt.js + Vue 3 + Tailwind CSS. NOT a React/shadcn project.
> shadcn gate: not applicable.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind CSS utility classes + CSS custom properties) |
| Preset | not applicable |
| Component library | none (hand-rolled Vue components following Obsidian Lens spec) |
| Icon library | Material Symbols Outlined (loaded via Google Fonts, `material-symbols-outlined` class) |
| Font | Manrope (display/headlines, weights 400/700) + Inter (body/labels, weights 400/700) |

Source: `nexio-web/DESIGN.md`, `nexio-web/tailwind.config.ts`, `nexio-web/assets/css/main.css`

### Design North Star

"Obsidian Lens" — dark cinematic glassmorphism. Interfaces are physical environments of dark glass, ink-black obsidian, and focused light. Use intentional asymmetry. Layers define depth; borders never do. Profile management panels are film-grade, not form-grade.

## Spacing Scale

All spacing is Tailwind's default 4px base. The project uses 8pt rhythm throughout (gap-2 = 8px, gap-4 = 16px, gap-6 = 24px, gap-8 = 32px).

| Token | Tailwind | Value | Usage |
|-------|----------|-------|-------|
| xs | gap-1 / p-1 | 4px | Icon-only gaps, tight inline padding |
| sm | gap-2 / p-2 | 8px | Badge internal padding, chip gaps |
| md | gap-4 / p-4 | 16px | Default element spacing, card inner padding |
| lg | gap-6 / p-6 | 24px | Section padding, card-to-card gap |
| xl | gap-8 / p-8 | 32px | Layout column gaps, panel top padding |
| 2xl | gap-12 | 48px | Major section breaks between panels |
| 3xl | gap-16 | 64px | Page-level top/bottom breathing room |

Exceptions:
- Profile avatar circle: 48px × 48px minimum (touch/click target). 80px × 80px for the ProfileCard display size.
- Photo upload drop zone: minimum 120px × 120px.
- Profile card grid gap: 24px (gap-6) — tighter than generic 32px xl to keep the grid cohesive.

Source: confirmed from existing component patterns in `CatalogInventory.vue`, `FormatterWorkspace.vue`, `PortalShell.vue`

## Typography

All sizes use the existing Manrope + Inter dual-typeface strategy. No new font sizes are introduced.

| Role | Size | Tailwind | Weight | Line Height | Font | Usage |
|------|------|----------|--------|-------------|------|-------|
| Meta | 10px (0.625rem) | text-[10px] | 700 (bold) | 1.0 | Inter | Section eyebrows in all-caps + 0.18em tracking, form labels, metadata chips, uppercase tracking labels, badge pattern (matches existing badge pattern) |
| Body | 14px (0.875rem) | text-sm | 400 (regular) | 1.6 | Inter | Card descriptions, helper text, panel body copy |
| Heading | 18px (1.125rem) | text-lg | 700 (bold) | 1.25 | Manrope | Panel section titles, profile name in card |
| Display | 32px (2rem) | text-4xl | 700 (bold) | 1.1 | Manrope | Profile dashboard page hero title ("Manage Profiles") |

**Weights in use:** 400 (regular) for body copy; 700 (bold) for all emphasis — Meta eyebrows, Heading titles, Display hero. No other weights.

Pairing rule: all-caps `text-[10px] font-bold tracking-[0.18em] text-zinc-500` eyebrow label above `text-lg font-bold text-on-surface` section heading — this is the existing "High-Low" signature already used in FormatterWorkspace and CatalogInventory.

Source: DESIGN.md §3, confirmed from `FormatterWorkspace.vue`, `CatalogInventory.vue`, `main.css`

## Color

All tokens are already defined in `tailwind.config.ts` and `main.css`. No new color values are introduced.

| Role | Token / Hex | CSS Var | Usage |
|------|-------------|---------|-------|
| Dominant (60%) | `#0e0e0e` | `--surface` / `bg-surface` | Page background, main content area |
| Container (30%) | `#1a1a1a` | `--surface-container` / `bg-surface-container` | Profile cards, detail panels, section containers |
| Secondary surface | `#131313` | `--surface-container-low` | Input fills, filter bars, nested containers |
| Accent — Primary (10%) | `#ba9eff` → `#8455ef` | `--primary` → `--primary-dim` | Primary CTA buttons (gradient), active sidebar nav indicator, focus ring on inputs, active profile selection state |
| Accent — Secondary | `#53ddfc` | `--secondary` | Status indicators (linked Trakt/Simkl), visible catalog count, informational badges |
| On-surface | `#ffffff` | `--on-surface` | Heading text, profile name text |
| On-surface-variant | `#adaaaa` | `--on-surface-variant` | Body text, descriptions, placeholder text |
| Destructive | `#ff7b82` | `--danger` | Delete profile button, unlink confirmation, delete confirmation dialog border |
| Ghost border | `rgba(73,72,71,0.15)` | `--stroke` | Card borders (felt, not seen) |

**60/30/10 surface split:**
- 60% dominant: `bg-surface` (#0e0e0e) — page, PortalShell main area
- 30% secondary: `bg-surface-container` (#1a1a1a) — ProfileCard bodies, ProfileDetailShell, section panels
- 10% accent: Electric Violet (`#ba9eff`) reserved strictly for: primary CTA gradient fill, active sidebar nav left-border + bg tint, focused input ring + bottom glow, selected/active profile card ring

**The No-Line Rule** (from DESIGN.md §2): Profile cards must NOT use a solid 1px border for layout containment. Use background shift (`bg-surface-container` on `bg-surface`) and the ghost border (`border-outline-variant/10`) only.

Source: DESIGN.md §2, `tailwind.config.ts`, `main.css`

|-------|-------|-----------------|

## Component Inventory

New components introduced in Phase 5. All follow existing Tailwind class vocabulary.

### ProfileDashboard

Layout container for the profile grid. Inserted as a new view in `account.vue` (`v-else-if="activeView === 'profiles'"`).

- Outer: `space-y-6 pb-12` — matches FormatterWorkspace/CatalogInventory outer wrapper
- Hero: `PortalManagementHero` with eyebrow `"Account Management"`, title `"Profiles"`, description: `"Create, rename, and delete profiles. Click a profile to manage its auth, catalogs, and formatter settings."`
- Grid: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 gap-6` — max 4 cards (max 4 profiles enforced by INFRA-02)
- Add Profile button: shown only when profile count < 4. Renders as a dashed-border card in the same grid slot: `rounded-xl border-2 border-dashed border-outline-variant/20 bg-surface-container/30 flex items-center justify-center h-[140px] hover:border-primary/30 transition-colors`

### ProfileCard

Each profile shown as a card in the dashboard grid.

- Outer: `rounded-xl border border-outline-variant/10 bg-surface-container p-5 flex flex-col gap-4 hover:border-primary/20 transition-colors cursor-pointer`
- Active/selected: add `ring-1 ring-primary/40`
- Avatar area: 80px × 80px circle. If `avatarUrl` set: `<img>` with `rounded-full object-cover w-20 h-20`. If no photo: colored circle using existing `ProfileAvatarColors` palette, initial letter in Manrope bold centered.
- Profile name: `text-lg font-bold font-display text-on-surface truncate`
- Profile index badge: `text-[10px] font-bold uppercase tracking-[0.18em] text-zinc-500` — e.g. `"Profile 1"`, `"Profile 2"`
- Primary profile indicator: small badge `"Master"` in `text-[10px] font-bold uppercase text-primary bg-primary/10 border border-primary/20 px-2 py-0.5 rounded-full`
- Footer action row: `flex items-center justify-between mt-auto`
  - Left: `"Manage"` button as `text-sm font-semibold text-primary hover:underline`
  - Right (non-primary profiles only): delete icon button — `rounded-full p-2 text-zinc-600 hover:text-danger hover:bg-danger/10 transition-colors` with `aria-label="Delete {profile name}"` (e.g. `aria-label="Delete Profile 2"`)

### ProfileDetailShell

Full-width panel that replaces the dashboard grid when a profile is selected. Shares structure with `PortalShell`'s main content area.

- Back link: `"← All Profiles"` in `text-sm text-zinc-500 hover:text-zinc-300 transition-colors mb-6 inline-flex items-center gap-2`
- Profile identity header: avatar (80px circle) + name (`text-2xl font-black font-display`) + index badge — left-aligned, 24px gap
- Tab bar: horizontal pill tabs for `Auth`, `Catalogs`, `Formatter`
  - Tab: `px-5 py-2 rounded-full text-sm font-semibold transition-colors`
  - Active: `bg-primary/10 text-primary border border-primary/20`
  - Inactive: `text-zinc-500 hover:text-zinc-300`
- Tab content: `mt-6 space-y-6`

### ProfileEditorSection (within ProfileDetailShell header)

Name edit + photo upload inline with the identity header.

- Profile name: inline editable `<input>` that activates on click — `bg-transparent border-b-2 border-transparent focus:border-primary/50 outline-none text-2xl font-black font-display text-on-surface transition-colors`
- Save name button: appears only when name is dirty — `rounded-xl bg-primary/10 border border-primary/20 px-4 py-1.5 text-sm font-semibold text-primary transition hover:bg-primary/20`
- Photo upload: `ProfilePhotoUpload` component (see below)

### ProfilePhotoUpload

Avatar photo upload control, used within ProfileDetailShell header.

- Trigger: click on avatar circle opens file picker (`<input type="file" accept="image/*" class="hidden">`)
- Hover overlay on avatar: semi-transparent `bg-black/50 rounded-full flex items-center justify-center` with camera icon (Material Symbols: `photo_camera`)
- Upload state: spinner overlay on avatar circle while uploading
- Remove photo link: shown below avatar when photo exists — `text-xs text-zinc-500 hover:text-danger transition-colors mt-1`
- Accepted: `image/jpeg`, `image/png`, `image/webp`. Max display: 256×256px (server-side resize per D-15).
- Error inline: `text-xs text-danger mt-1` below the avatar area

### ProfileAuthTab (per-profile Auth sub-panel)

Reuses `SettingsWorkspace` pattern. Shows Trakt + Simkl link/unlink for the selected profile.

- Section header: same eyebrow/title pattern as other panels
- Profile context indicator chip: `"Managing: {profile name}"` in `text-xs font-bold uppercase tracking-[0.18em] text-secondary bg-secondary/10 border border-secondary/20 px-3 py-1 rounded-full` — rendered above the link/unlink controls
- Trakt block: reuses existing Trakt device-flow UI from `SettingsWorkspace` / integrations view, scoped to selected profile
- Simkl block: same, scoped to selected profile
- Linked state indicator: `"Linked"` badge in secondary cyan color (`text-secondary bg-secondary/10 border border-secondary/20`)
- Unlinked state: `"Not linked"` in `text-zinc-500`

### ProfileCatalogsTab

Direct reuse of `CatalogInventory.vue` component, scoped to selected profile ID. No new component needed — pass `profileId` prop.

### ProfileFormatterTab

Direct reuse of `FormatterWorkspace.vue` component, scoped to selected profile ID. No new component needed — pass `profileId` prop.

### DeleteProfileModal

Confirmation modal for profile deletion. Teleported to `<body>` following `FormatterWorkspace` snippets/advanced modal pattern.

- Overlay: `fixed inset-0 z-[80] flex items-center justify-center bg-black/70 p-4 backdrop-blur-sm`
- Modal: `w-full max-w-md rounded-3xl border border-danger/30 bg-[#151517] shadow-2xl p-6 space-y-4`
- Title: `"Delete {profile name}?"` in `text-lg font-bold text-on-surface`
- Body: `"This will permanently remove this profile and all its settings. This cannot be undone."` in `text-sm text-on-surface-variant`
- Actions: `flex gap-3 justify-end mt-2`
  - Cancel: `secondary-btn` (existing CSS class)
  - Confirm delete: `danger-btn` (existing CSS class) with label `"Delete Profile"`

## Glassmorphism Rules (Phase 5 specific)

These extend DESIGN.md §4 for the new components.

1. **ProfileCard**: `bg-surface-container` (solid, not glass). Cards are mid-layer, not floating. Use ghost border `border-outline-variant/10`.
2. **ProfileDetailShell**: same as ProfileCard — solid mid-layer.
3. **DeleteProfileModal**: `bg-[#151517]` with `border border-danger/30`. No backdrop blur on the modal itself (blur is on the overlay only).
4. **ProfilePhotoUpload overlay**: `bg-black/50 backdrop-blur-sm rounded-full` — light blur acceptable because it is a small floating micro-surface.
5. **Profile context indicator chip**: no blur. Flat `bg-secondary/10`.
6. **Luminescent Scrim**: existing `bg-secondary/5` radial blur in PortalShell top-right corner already covers the dashboard — do not add a second scrim.
