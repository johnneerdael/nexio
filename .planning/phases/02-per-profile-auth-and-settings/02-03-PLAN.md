## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Profile A settings -> Profile B read | Profile 2 must not see Profile 1's theme, layout, player, or search history preferences |
| Init block -> active profile | init block migrations run once on profile 1's DataStore at app startup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Information Disclosure | PlayerSettingsDataStore | mitigate | All flow properties wrapped in `flatMapLatest(activeProfileId)`; `store()` resolves at call time; compiler enforces removal of `dataStore` field |
| T-02-08 | Information Disclosure | LayoutPreferenceDataStore | mitigate | `profileFlow` helper wraps ALL flow properties in `flatMapLatest`; single choke point makes audit trivial |
| T-02-09 | Tampering | LayoutPreferenceDataStore.init | accept | Init block runs `store().edit` which resolves to profile 1 at app startup. Accepted: Singleton init runs at Hilt injection time, before any UI interaction is possible; profile switch requires UI action |
| T-02-10 | Information Disclosure | SearchHistoryDataStore | mitigate | Per D-03, search history is per-profile for privacy; `flatMapLatest` ensures isolation; verified by ThemeDataStoreProfileTest pattern |
