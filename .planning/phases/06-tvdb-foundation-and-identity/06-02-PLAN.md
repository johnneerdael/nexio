<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings DataStore to TVDB login | Local API key and optional PIN become a network login body. |
| TVDB login response to local token cache | Bearer token persists locally and is reused for authenticated requests. |
| NetworkModule to all provider clients | New TVDB Retrofit binding must not alter existing TMDB client behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Information Disclosure | TvdbAuthService | mitigate | Omit blank PIN, never log request body, API key, PIN, token, or Authorization header; grep enforces no secret names in Log calls. |
| T-06-02-02 | Denial of Service | TvdbAuthService | mitigate | Use a `Mutex` around token refresh so concurrent callers perform one login. |
| T-06-02-03 | Spoofing | TvdbAuthService | mitigate | Treat 401 as invalid credentials, clear token, and mark status `INVALID` instead of reusing stale bearer tokens. |
| T-06-02-04 | Information Disclosure | TvdbTokenStore | accept | Token is local app state following existing DataStore credential pattern; remote sync remains secret-backed in Plan 06-04. |
</threat_model>
