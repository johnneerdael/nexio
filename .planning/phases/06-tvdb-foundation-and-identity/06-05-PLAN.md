<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input to ViewModel | API key and PIN enter app state through the credentials dialog. |
| ViewModel to auth service | Credentials are passed to validation and token caching. |
| Settings status to user | Validation/fallback state is displayed without revealing secret material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05-01 | Information Disclosure | TvdbSettingsScreen | mitigate | Mask API key outside dialog, never display PIN after save, and keep copy free of credential/token values. |
| T-06-05-02 | Spoofing | TvdbSettingsViewModel | mitigate | Enable TVDB only after `TvdbAuthService.validateCredentials` returns true. |
| T-06-05-03 | Denial of Service | TvdbSettingsViewModel | mitigate | Ignore duplicate save actions while validation is in progress. |
| T-06-05-04 | Information Disclosure | Settings feedback | mitigate | Use settings-local validation/status feedback only; no browse-time toasts/snackbars with provider failure details. |
</threat_model>
