## Phase Screen Contract

TVDB must appear under the existing Integration settings hub, near TMDB and other metadata providers. Because TVDB credentials and sync state are shared account-level integration settings, the entry follows the existing primary-profile-only pattern used for shared integrations.

The TVDB detail screen contains one compact settings group unless the implementation needs a second read-only group for precedence copy. The preferred row order is:

1. Enable TVDB - `SettingsToggleRow`.
2. TVDB credentials - `SettingsActionRow`, opens the credentials dialog.
3. TVDB status - disabled `SettingsActionRow` with state value and explanatory subtitle.
4. Provider precedence - disabled `SettingsActionRow` or `SettingsGroupCard` text block using the copy above.

Do not add per-surface toggles for artwork, trailers, cast, related content, networks, or episodes in Phase 6. Those controls are explicitly out of scope.

Primary visual anchor: the focused Enable TVDB row. Secondary emphasis: the TVDB status row value, which communicates whether credentials are not configured, validating, valid, invalid, or fallback active.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Initial focus | The Enable TVDB row receives focus when entering the TVDB detail pane from the integration hub. |
| DPAD navigation | Preserve existing settings behavior: Right enters detail, Left returns focus to the rail or integration hub, Back returns from TVDB detail to the integration hub. |
| Enable without credentials | Do not silently enable active TVDB. Keep status Not configured and surface "TVDB API key is required" through settings feedback. |
| Enable with invalid credentials | Keep TVDB inactive for provider use, status Invalid, and show the corrective copy. |
| Validation in progress | Show status Validating, change primary CTA to "Saving credentials...", and ignore duplicate save actions until validation completes. |
| Validation success | Close dialog, mask the credential row value, set status Valid, and allow TVDB to be active if the toggle is on. |
| Validation failure | Keep dialog open if practical, set status Invalid, show invalid-copy feedback, and never log or display API key, PIN, or bearer token. |
| Active but unusable fallback | Do not show browse-time toasts or snackbars. Settings status must show Fallback active or Last failure, and logs must contain a sanitized reason. |
| Clear credentials | Clear API key, optional PIN, cached token state, and validation state; return row value to Not set and status to Not configured. |
| Optional PIN | PIN is accepted in the same credentials dialog, stored secret-backed, omitted from display, and sent only when non-blank. |

Credential dialog contract:

| Element | Contract |
|---------|----------|
| Dialog shell | Existing `NexioDialog`, width 700dp, 16dp radius, elevated background, 1dp border |
| API key field | Existing BasicTextField-in-Card pattern, single line, focused border 2dp `NexioColors.FocusRing` |
| Optional PIN field | Same field style as API key, placed below it with 8dp or 16dp vertical spacing |
| Buttons | Right-aligned row: Close credentials, Clear TVDB credentials, Save credentials |
| Secret display | API key masked outside dialog; PIN never shown after save |

## Accessibility And TV Input

Every interactive row must remain at least 62dp tall. Focus scale stays `1f`; focus is communicated by the existing 2dp focus border and text color, not by layout growth. Row titles and values are single-line with ellipsis; provider-precedence body may wrap but must stay inside the group card without occluding following rows.

Touch is secondary on Android TV, but any icon-only control introduced by implementation must have a minimum 44dp target. This phase should not require icon-only controls.
