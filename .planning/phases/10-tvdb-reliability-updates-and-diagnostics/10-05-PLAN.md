<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Diagnostics store -> settings UI | Internal provider/cache/fallback decisions become user-visible text. |
| Docs -> user configuration | Documentation can cause incorrect credential/provider setup if precedence is vague. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05-01 | Information Disclosure | `TvdbDiagnosticsDataStore` / settings UI | mitigate | Persist only sanitized diagnostics and display reason/status strings, not API keys, PINs, bearer tokens, or headers. |
| T-10-05-02 | Repudiation | Debug diagnostics | mitigate | Show exact reason-code-backed fields for provider choice, fallback, missing `airsTime`, date-only gating, poster override, skipped TMDB TV fetches, refresh status, stale cache, and invalid credentials. |
| T-10-05-03 | Spoofing | user docs | mitigate | Docs state provider precedence exactly: TVDB for TV when configured, TMDB for movies and explicit TV fallback, poster-ratings for supported posters. |
</threat_model>
