Create `TvdbCredentialHealth.kt` in package `com.nexio.tv.core.tvdb` per D-03 and D-08 so app-start catch-up/background polling never retry-storms when credentials are invalid:
```kotlin
enum class TvdbCredentialStatus { UNKNOWN, VALID, INVALID }
data class TvdbCredentialHealthState(val status: TvdbCredentialStatus, val lastError: String? = null)
class TvdbCredentialHealth @Inject constructor(...) {
    val state: Flow<TvdbCredentialHealthState>
    suspend fun markValid()
    suspend fun markInvalid(error: String?)
    suspend fun canCallTvdb(): Boolean
}
```
Store only status and sanitized error text. Do not store API key, PIN, bearer token, or Authorization header.

Create `TvdbUpdateCoordinator @Inject constructor(processor: TvdbUpdateProcessor, credentialHealth: TvdbCredentialHealth, updateStateStore: TvdbUpdateStateStore)` with:
```kotlin
companion object {
    const val UNIQUE_WORK_NAME = "tvdb-update-refresh"
    val UPDATE_INTERVAL: Duration = Duration.ofHours(12)
}
suspend fun catchUpUpdates(trigger: TvdbUpdateTrigger): TvdbUpdateCoordinatorResult
fun schedulePeriodicUpdates(workManager: WorkManager)
```

`catchUpUpdates` must call `credentialHealth.canCallTvdb()` before `processor.processSince()`. If false, record `NETWORK_CALL_BLOCKED`, return `BlockedInvalidCredentials`, and do not call the processor. `schedulePeriodicUpdates` must enqueue unique periodic work using `ExistingPeriodicWorkPolicy.UPDATE`, `NetworkType.CONNECTED`, and the exact unique name `tvdb-update-refresh`.

Wire credential and scheduling producers to D-10 diagnostics: inject or pass `TvdbDiagnosticsRecorder` where credential status and coordinator decisions are made. `markInvalid` must record sanitized `INVALID_CREDENTIALS`; `catchUpUpdates` must record sanitized `NETWORK_CALL_BLOCKED`, `UPDATE_REFRESH_STARTED`, `UPDATE_REFRESH_SUCCEEDED`, and `UPDATE_REFRESH_FAILED` at the coordinator boundary. Emit structured logs using `TvdbReliabilityDiagnostic.structuredLogFields()` only. Do not log Authorization headers, API keys, PINs, bearer tokens, raw responses, or full request URLs.

Create `TvdbUpdateWorker` under `com.nexio.tv.workers` using `@HiltWorker`, `@AssistedInject`, and `CoroutineWorker`. `doWork()` delegates to `coordinator.catchUpUpdates(TvdbUpdateTrigger.WORKER)`. Return `Result.success()` for success and blocked invalid credentials, `Result.retry()` for transient network/update failures.

Inject `TvdbUpdateCoordinator` in `NexioApplication` and, in `onCreate`, call `tvdbUpdateCoordinator.schedulePeriodicUpdates(WorkManager.getInstance(this))` and launch `tvdbUpdateCoordinator.catchUpUpdates(TvdbUpdateTrigger.STARTUP)` on the existing `appScope`. Do not call this from normal metadata read paths.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App lifecycle -> TVDB network | Startup and worker code can call external TVDB APIs. |
| Stored credential status -> network gate | Local health state decides whether new TVDB calls are allowed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02-01 | Denial of Service | `TvdbUpdateWorker` | mitigate | Invalid credentials return handled success instead of WorkManager retry; network failures only retry through WorkManager policy. |
| T-10-02-02 | Information Disclosure | `TvdbCredentialHealth` | mitigate | Persist only `UNKNOWN`, `VALID`, `INVALID`, and sanitized error strings; no API key, PIN, bearer token, or auth header fields. |
| T-10-02-03 | Repudiation | `TvdbUpdateCoordinator` | mitigate | Record `UPDATE_REFRESH_STARTED`, `UPDATE_REFRESH_SUCCEEDED`, `UPDATE_REFRESH_FAILED`, and `NETWORK_CALL_BLOCKED` reasons. |
</threat_model>
