# Path 04 — Detail media

- **Review SHA:** `39b0df54ae5845f525de37791ff99356e2364044`
- **Lane:** B (router) + A (runtime) + I (trace mode) + C (provider contracts — posters)
- **Contract:** Detail-screen artwork (backdrop / logo) and trailer playback are expected to flow through a `DETAIL_MEDIA`-depth fetch via the canonical facade chain (`MetadataRouterFacade` → `MetadataRouter` → `ProviderPlanExecutor` → `ProviderPlanRunner` → adapter → `IntegrationRuntime` → `FieldResolver`), with `ResolverOrchestrator.schedule(DETAIL_MEDIA)` adding `ARTWORK` (local) and `TRAILERS` (network) on top of `ADDON_DISPLAY`. Premium artwork (TopPosters / RPDB) may override `POSTER` at render time but must NEVER override `TITLE`, `OVERVIEW`, or `EPISODE_LIST`.

- ✅ `POSTER` selection allows premium override at the **render** layer: `app/src/main/java/com/nexio/tv/core/image/IntegrationPosterFetcher.kt:23-37` (Coil `Fetcher` short-circuits to `RpdbIntegrationProvider` / `TopPostersIntegrationProvider`); URL-tagging at `app/src/main/java/com/nexio/tv/core/image/ArtworkImageCacheKeys.kt:7-30`. - ✅ `TITLE` / `OVERVIEW` are NOT eligible for premium override at the metadata-document layer: `FieldResolver.resolve(...)` (`app/src/main/java/com/nexio/tv/core/metadata/router/FieldResolver.kt:30-60`) always sets `owners[field] = FieldOwner.PRIMARY` for primary candidate fields and rejects every secondary attempt with `"primary already filled the field"` (line 55). Premium poster providers (`IntegrationProvider.RPDB`, `IntegrationProvider.TOP_POSTERS`) are not registered as `MetadataProviderAdapter`s, so they cannot enter `FieldResolver` as candidates at all.
- ✅ Cross-cutting trace rule enforces the same invariant: `app/src/main/java/com/nexio/tv/core/trace/TraceValidationRules.kt:171-185` — `SecondaryDoesNotOverwritePrimary` flags any `metadata.field_selected` event for `TITLE` / `OVERVIEW` / `EPISODE_LIST` that carries a non-empty `rejectedCandidates` list, marking the trace as failed.

## Verdict

❌ **FAIL** — The DETAIL_MEDIA depth is plumbed in models / orchestrator / plan-executor and unit-tested, but **never invoked from production code**. Trailers and artwork that the contract assigns to DETAIL_MEDIA actually flow through (a) the existing DETAIL_CORE response (artwork) and (b) `TrailerService` → `TrailerTmdbProvider` → `TmdbIntegrationProvider` (trailers, bypassing the canonical facade). Premium-poster ownership is correctly enforced at the rendering layer and via the `SecondaryDoesNotOverwritePrimary` trace rule, so that part of the contract is satisfied independently of DETAIL_MEDIA.

## Findings

### F-04-01: `MetadataDepth.DETAIL_MEDIA` has no production caller (P1)

- **Where:** Repo-wide search for `MetadataDepth.DETAIL_MEDIA` shows three production hits (`app/src/main/java/com/nexio/tv/core/metadata/router/MetadataModels.kt:21` enum decl; `app/src/main/java/com/nexio/tv/core/metadata/router/ResolverOrchestrator.kt:29` schedule branch; `app/src/main/java/com/nexio/tv/core/metadata/router/ProviderPlanExecutor.kt:58` plan branch) plus seven unit-test references. Zero call-sites that *request* this depth.
- **What:** No consumer ever calls `metadataRouterFacade.fetchTvEnrichment(... depth = MetadataDepth.DETAIL_MEDIA)` (or any other depth-aware facade method) with `DETAIL_MEDIA`. The detail VM only ever issues `DETAIL_CORE` (`MetaDetailsViewModel.kt:1347-1361`) and home enrichment also stays on `DETAIL_CORE` (Path 02 chain step 3).
- **Impact:** The whole DETAIL_MEDIA pathway is dead code from the consumer's perspective. The contract asserts a separate enrichment depth for media (artwork + trailers) but production collapses both into DETAIL_CORE (artwork) or routes around the facade entirely (trailers). Trace events `metadata.resolver_schedule(depth=DETAIL_MEDIA)`, `metadata.route_decision(depth=DETAIL_MEDIA)`, `metadata.provider_plan(...MOVIE_VIDEOS)`, `metadata.field_selected(...TRAILER_LIST)` cannot fire.
- **Severity:** P1.
- **Fix sketch:** Either (a) wire the detail VM to issue a follow-up `metadataRouterFacade.fetch...(... depth = DETAIL_MEDIA)` after first paint (preferred — restores observability and keeps trailer/artwork inside the canonical chain), or (b) remove `DETAIL_MEDIA` from the depth enum / orchestrator / plan executor and document the actual collapsed-into-DETAIL_CORE behaviour as the contract.

### F-04-02: `ResolverOrchestrator` is never invoked from the metadata facade chain (P1)

- **Where:** `app/src/main/java/com/nexio/tv/core/metadata/router/ResolverOrchestrator.kt`.
- **What:** `ResolverOrchestrator.schedule(depth)` is the sole emitter of `metadata.resolver_schedule`. Nothing in `MetadataRouterFacade.resolveRequest(...)` (`MetadataRouterFacade.kt:33-66`) constructs or calls a `ResolverOrchestrator`. Outside of unit tests, the class has no production callers — the `@Singleton` Hilt binding builds an instance whose `schedule(...)` is never invoked.
- **Impact:** `metadata.resolver_schedule` events never appear in any production trace, on any depth (PREVIEW, DETAIL_CORE, DETAIL_MEDIA, DETAIL_SECONDARY, SEASON, PLAYER). The `scheduled` / `skipped` taxonomy that the contract relies on for "what resolvers ran for this depth" is silent everywhere.
- **Severity:** P1.
- **Fix sketch:** Have `MetadataRouterFacade.resolveRequest(...)` call `resolverOrchestrator.schedule(request.depth)` immediately after route/identity resolution, before the plan executes; gate the local/network resolvers list it returns onto the actual adapters that run.

### F-04-03: Trailer enrichment bypasses the canonical metadata facade (P1)

- **Where:** `app/src/main/java/com/nexio/tv/ui/screens/detail/MetaDetailsViewModel.kt:2660-2700` (`fetchTrailerUrl` calling `trailerService.resolveTrailer(...)` at line 2680). Service: `app/src/main/java/com/nexio/tv/data/trailer/TrailerService.kt:54-80`. TMDB videos call: `app/src/main/java/com/nexio/tv/data/integration/trailer/TrailerTmdbProvider.kt:30-80` (uses `TmdbIntegrationProvider` directly).
- **What:** When the trailer button is pressed (or auto-trailer fires), the VM goes `MetaDetailsViewModel → TrailerService → {TrailerTmdbProvider | TvdbTrailerResolver | TrailerBackendProvider} → IntegrationProvider`. `MetadataRouterFacade`, `MetadataRouter`, `ProviderPlanExecutor`, `ProviderPlanRunner`, `FieldResolver`, `ResolverOrchestrator` are *all* skipped. `IntegrationRuntime` still gets the call (via `TmdbIntegrationProvider`), so `runtime.operation_start` / `runtime.operation_finish` / `runtime.cache_decision` / `http.*` still fire — but with no `metadata.route_decision` / `metadata.provider_plan` / `metadata.field_selected` correlation.
- **Impact:** Same observability + ownership-enforcement gap as F-03-02 (movie DETAIL_CORE bypass), in a different lane: the contract's assertion that DETAIL_MEDIA flows through the canonical chain is false for trailers. Premium-source / multi-provider ownership rules cannot apply to trailer selection because the trailer pipeline never enters `FieldResolver`.
- **Severity:** P1.
- **Fix sketch:** Introduce a `TRAILER_LIST` (or similar) `ResolvedField`; have `TrailerTmdbProvider` / `TvdbTrailerResolver` participate as candidates inside `MetadataProviderAdapter` returns for the `MOVIE_VIDEOS` / `TV_VIDEOS` plan steps; have the detail VM call the facade with `DETAIL_MEDIA` and read trailers off the resolved doc instead of going through `TrailerService` for the metadata side. Keep `TrailerService` for *playback*-stage concerns (YouTube extraction, playback-source resolution).

### F-04-04: Detail-screen artwork is collapsed into DETAIL_CORE response, not a separate DETAIL_MEDIA fetch (P2)

- **Where:** `app/src/main/java/com/nexio/tv/ui/screens/detail/MetaDetailsViewModel.kt:1418-1419, 1448-1454`. `backdrop` / `logo` are read from `tvEnrichment` / `tmdbEnrichment` (the DETAIL_CORE return values), then merged into the `Meta` object inside the same `enrichMeta` method that issued the DETAIL_CORE call.
- **What:** ARTWORK is not requested as a separate resolver pass; it is whatever the primary (TVDB / TMDB) `*_CORE` endpoint already returned. There is no second facade round-trip with `DETAIL_MEDIA`, no `ResolverType.ARTWORK` resolver class anywhere in production (`grep -rn "ResolverType\." app/src/main` shows the enum only being read inside the orchestrator and `MetadataModels.kt`).
- **Impact:** Architecturally the DETAIL_MEDIA contract is unfulfilled for artwork, but the user-visible behaviour is roughly equivalent because *_CORE responses already include the backdrop/logo fields. This is a documentation/architecture gap rather than a missing-data bug. It also explains why no `ARTWORK` resolver implementation exists (the enum value is decorative).
- **Severity:** P2.
- **Fix sketch:** Either implement an `ArtworkResolver` that runs at DETAIL_MEDIA depth (and have `IntegrationPosterFetcher` participate in artwork selection through an adapter), or strike the `ResolverType.ARTWORK` branch from `ResolverOrchestrator.schedule(DETAIL_MEDIA)` and document artwork as DETAIL_CORE-collapsed.
