## What does NOT happen on this path (verified)

- ❌ No `SkipSegmentResolver` class exists in `app/src/main`. The contracted resolver is purely declarative (an enum constant).
- ❌ `MetadataResolutionResult.resolverSchedule.networkResolvers` is never iterated or dispatched anywhere in production — so even though `ResolverOrchestrator.schedule(PLAYER)` *does* fire under the PLAYER caller and *does* return `[TRACKING, SKIP_SEGMENTS]`, that list never causes a fetch.
- ❌ `SkipInterval` does not appear on `ResolvedMetadataDocument`, `TvMetadataEnrichment`, or any field-owner ledger. Skip intervals are state on `PlayerRuntimeController` (`PlayerRuntimeController.kt:262`), not on the metadata document.
- ❌ `FieldResolver` does not see skip-segment candidates and there is no per-field ownership rule for skip data in `TraceValidationRules` (closest analogue: `SecondaryDoesNotOverwritePrimary` for TITLE/OVERVIEW/EPISODE_LIST).

## Verdict

⚠ **PARTIAL FAIL** — The PLAYER-depth canonical chain DOES exist for this path (a positive finding distinguishing it from Path 04: `MetadataDepth.PLAYER` actually has a production caller, so `metadata.resolver_schedule` and `metadata.route_decision` fire here). HTTP egress for skip providers is correctly contained inside `IntegrationRuntime` via `IntegrationSpec`. However: (a) no `SkipSegmentResolver` class exists, the schedule's `SKIP_SEGMENTS` entry is decorative, and (b) skip intervals are fetched on a parallel `SkipIntroRepository` lane that bypasses the facade/router/plan/field-resolver — same anti-pattern shape as F-04-03 (trailers) and F-05-02..04 (reviews/recommendations/cast).

## Findings

### F-12-01: `ResolverType.SKIP_SEGMENTS` has no resolver implementation (P1)

- **Where:** `app/src/main/java/com/nexio/tv/core/metadata/router/MetadataModels.kt:28,53,64` (enum decls); `app/src/main/java/com/nexio/tv/core/metadata/router/ResolverOrchestrator.kt:45` (only producer). Repo-wide search for `SkipSegmentResolver`, `class.*SkipSegment`, `SkipResolver` returns zero matches.
- **What:** The orchestrator promises that `SKIP_SEGMENTS` will be scheduled at PLAYER depth, but there is no class — interface or implementation — that consumes `ResolverType.SKIP_SEGMENTS` and turns it into a fetch. `MetadataResolutionResult.resolverSchedule.networkResolvers` is computed but never iterated by the facade (`MetadataRouterFacade.resolveRequest(...)` returns it as a data field; `fetchTvEnrichment(...)` discards it entirely on lines 74-79).
- **Impact:** The contract's "PLAYER depth via canonical facade fans skip segments through `SkipSegmentResolver`" is structurally unfulfillable. The `metadata.resolver_schedule` trace event lists `SKIP_SEGMENTS` as `scheduled`, which is misleading — it implies a resolver ran when none exists. No `ResolvedField.SKIP_INTERVALS` exists either, so even if a resolver were added, `FieldResolver` would have no slot to write to.
- **Severity:** P1.
- **Fix sketch:** Either (a) introduce a `SkipSegmentResolver` interface + a `ResolvedField.SKIP_INTERVALS`, plumb it into `FieldResolver.resolve(...)`, and have the facade actually dispatch `resolverSchedule.networkResolvers` (couples the fix to F-04-02-style facade dispatch); or (b) remove `SKIP_SEGMENTS` from `ResolverType` / orchestrator and document `SkipIntroRepository` as the canonical skip-segment surface, with the controller calling it explicitly outside the metadata document model.

### F-12-02: Skip-segment fetch bypasses the canonical metadata facade (P1)

- **Where:** Caller: `app/src/main/java/com/nexio/tv/ui/screens/player/PlayerRuntimeControllerObservers.kt:443-498` (`fetchSkipIntervals`), invoked from `PlayerRuntimeControllerStreams.kt:777` and `PlayerRuntimeControllerObservers.kt:316,391`. Repository: `app/src/main/java/com/nexio/tv/data/repository/SkipIntroRepository.kt:97-105` and arbiter on lines 26-43. Providers: `app/src/main/java/com/nexio/tv/data/integration/skip/{AniSkip,Intro Db,AnimeSkip}IntegrationProvider.kt`.
- **What:** Skip intervals are issued from the controller as a side-effect of stream load, in parallel with — not driven by — the PLAYER-depth facade call. The facade chain (`MetadataRouterFacade` → `MetadataRouter` → `ProviderPlanExecutor` → `ProviderPlanRunner` → `FieldResolver`) is skipped for skip data; `SkipIntroRepository` carries its own arbiter (`SkipProviderArbiter.resolve(...)`) duplicating the role of `MetadataRouter` for the skip-provider routing decision (theintrodb vs aniskip vs animeskip vs arm). `IntegrationRuntime` is correctly used by all three providers, so `runtime.*` and `http.*` events still fire — but with no `metadata.route_decision` / `metadata.provider_plan` / `metadata.field_selected` correlation.
- **Impact:** Same observability gap as F-04-03 (trailer bypass), F-05-02 (reviews bypass), F-05-03 (recommendations bypass), F-05-04 (cast/organization-person bypass). Premium/multi-provider ownership rules cannot apply to skip-segment selection because the skip pipeline never enters `FieldResolver`. The PLAYER-depth claim that "SKIP_SEGMENTS is scheduled" is true at the schedule-emission level but false at the dispatch level.
- **Severity:** P1.
- **Fix sketch:** Couples to F-12-01's fix (a). Move `SkipProviderArbiter` logic into `MetadataRouter` (or an adjacent skip-router) so that the PLAYER-depth `MetadataRoute` includes the chosen skip provider; have the controller read `SkipInterval`s off the resolved document; keep `SkipIntroRepository`'s caches at the runtime layer (`IntegrationCachePolicy.CacheFirst` already provides equivalent semantics — the in-memory `ConcurrentHashMap` cache on `SkipIntroRepository` becomes redundant once skip data is a `ResolvedField`).
