# Path 02 — Home visible item enrichment

- **Review SHA:** `39b0df54ae5845f525de37791ff99356e2364044`
- **Lane:** B (metadata router) + A (runtime) + I (trace mode)
- **Contract:** When a Home tile becomes focused (or a hero/adjacent neighbour visibility event fires), enrichment goes through `MetadataRouterFacade` → `MetadataRouter` → `ProviderPlanExecutor.buildPlan` → `ProviderPlanRunner.run` → adapter `execute()` → `IntegrationRuntime.get(spec)` → `FieldResolver.resolve(...)` → enriched `HomeDisplayMetadata`. Cache HIT short-circuits network. `FieldResolver` is the SOLE final-field producer for non-PREVIEW depths.

## What does NOT happen on this path (verified)

- ❌ NO bypass of `MetadataRouterFacade`. UI does not import or call `MetadataRouter`/`ProviderPlanRunner`/`FieldResolver` directly on this path; the only route in is `metadataRouterFacade.fetchTvEnrichment(...)` (`HomeViewModelPresentationPipeline.kt:723, 743`).
- ❌ NO bypass of `FieldResolver` for `DETAIL_CORE`. `MetadataRouterFacade.toResolvedDocument()` (`MetadataRouterFacade.kt:157-169`, the secondary producer flagged by **B-Q3.1**) is gated behind `if (request.depth == MetadataDepth.PREVIEW)` (`MetadataRouterFacade.kt:37`) and is therefore unreachable on this path. For `DETAIL_CORE` the resolved doc is produced by `fieldResolver.resolve(...)` at `MetadataRouterFacade.kt:52`.
- ❌ NO `http.request` emission when the cache HIT branch runs. `RuntimeTraceInterceptor` only emits `http.request`/`http.response` when an actual OkHttp call is made; cache HIT short-circuits before `executeWithoutCache`/the network `IntegrationProvider` API call, so `chain.proceed(request)` is never invoked for that runtime operation.
- ❌ NO direct provider HTTP API call from the UI layer. All HTTP for this path is initiated inside `*IntegrationProvider` classes via `IntegrationRuntime.get(spec)` (e.g. `TmdbIntegrationProvider.kt:70` injects `IntegrationRuntime`; `IntegrationNetworkPermit` enforces this with the `"In-scope provider network call without IntegrationRuntime permit"` violation at `IntegrationNetworkPermit.kt:76`).
- ❌ NO use of the `defaultMetadataRouterFacadeForManualConstruction()` helper (`HomeProviderLocalizedMetadataOverlay.kt:62`) at runtime. That helper builds `ProviderPlanRunner(emptySet())` with empty in-memory anime/id stores and is only the default value for the `metadataRouterFacade` parameter when DI is not active. Hilt overrides the parameter with the DI-provided `MetadataRouterFacade` (which carries the real adapters and runtime).

## Verdict

✅ **Contract satisfied.** Visible-item enrichment goes through the canonical facade entry, the router enforces non-PREVIEW depth, the plan is executed by the adapter set bound through Hilt, the runtime owns cache decisions and operation-id minting (so the OkHttp interceptor can correlate `http.*` to `runtime.*`), and `FieldResolver` is the sole producer of the final `ResolvedMetadataDocument` for `DETAIL_CORE`. The only secondary `ResolvedMetadataDocument` producer in the facade (`toResolvedDocument`, **B-Q3.1**) is gated to PREVIEW depth and therefore not reachable on this path.

## Findings

### F-02-01 — `MetadataRouterFacade.fetchTvEnrichment` reuses Path-01 first-paint snapshot at the router pre-flight site

- **Severity:** low (process / observability hygiene; no incorrect data)
- **Lane:** I (trace mode) + B (metadata router)
- **Where:** `app/src/main/java/com/nexio/tv/ui/screens/home/HomeViewModelPresentationPipeline.kt:729, 749` — `addonMetadata = item.toFirstPaintHomeDisplayMetadata()`.
- **Observation:** Path 02's facade entry uses the *first-paint* wrapper to seed `MetadataSourceContext.addonMetadata`. That wrapper emits a `metadata.first_paint(routerExecuted=false, networkExecuted=false, surface=HOME, source=ADDON_META_PREVIEW)` event for the act of constructing the snapshot, even though the next thing this same coroutine does is invoke the router and (likely) the network. This is the exact misplacement reported in **F-01** of Path 01 and is the only first-paint emission site in production.
- **Impact:** A trace recording of a focus event will contain a `metadata.first_paint` event immediately followed by `metadata.route_decision` / `metadata.provider_plan` / `runtime.operation_start` for the same `contentId`. From the validator's perspective the event is technically truthful (the snapshot itself didn't route), but it is impossible to distinguish "first paint" from "router pre-flight enrichment of an already-painted tile" in the recorded trace.
- **Suggested next step (out of scope for Phase 3):** swap the call sites at `:729` and `:749` to the pure `item.toHomeDisplayMetadata()` and emit `metadata.first_paint` once-per-content-id from the `buildCatalogItem` boundary instead. Tracked under Path 01 finding F-01 and the Lane I follow-up.

### F-02-02 — Manual `MetadataRouterFacade` fallback constructor builds an adapter-empty router

- **Severity:** low (latent; production DI overrides it, but tests/snapshots may inadvertently exercise it)
- **Lane:** B (metadata router)
- **Where:** `app/src/main/java/com/nexio/tv/ui/screens/home/HomeProviderLocalizedMetadataOverlay.kt:62-77` (`defaultMetadataRouterFacadeForManualConstruction()`).
- **Observation:** The default value used by `HomeViewModel.metadataRouterFacade` (`HomeViewModel.kt:119`), `HomeViewModelContinueWatching` (`:209, :214, :338`), `HomeCatalogRefreshCoordinator` (`:70`), and `MetaDetailsViewModel.defaultMetadataRouterFacadeForManualConstruction()` (`MetaDetailsViewModel.kt:98-99`) constructs `MetadataRouterFacade(router=MetadataRouter(InMemoryAnimeIdentityIndex(), InMemoryIdMappingStore()), providerPlanRunner=ProviderPlanRunner(emptySet()), fieldResolver=FieldResolver(), …)`. With `adapters = emptySet()`, `ProviderPlanRunner.run(plan)` will throw `MetadataRouteFailure.MissingPlanStepAdapter` for every step (`ProviderPlanRunner.kt:35`).
- **Impact:** If anything ever exercises this fallback (e.g. a test instantiates `HomeViewModel` without injecting the facade, or DI fails silently), Path 02 enrichment will throw and `runCatching { fetchProviderEnrichmentForPreview(item) }.getOrNull()` (`HomeViewModelPresentationPipeline.kt:462, 536, 773`) will swallow the failure — Home tiles would silently never enrich. Cross-references **B-Q3.2**: the same file also instantiates a bare `FieldResolver()` outside DI.
- **Suggested next step (out of scope for Phase 3):** make the fallback constructor `error("MetadataRouterFacade must be DI-provided")` (or remove the default value and force injection at call sites), so missing wiring fails loudly instead of silently producing empty tiles.
