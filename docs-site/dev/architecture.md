# Architecture

## Purpose
Provide a high-level view of the Nexio documentation domains and their relationship to application behavior.

## Audience
- Contributors onboarding to the repository
- Maintainers planning or reviewing technical changes

## Prerequisites
- Familiarity with repository layout

## Procedure and Guidance
1. Use [Web Overview](../web/index.md) for admin and configuration workflows.
2. Use [Android Overview](../android/index.md) for runtime UX and playback behavior.
3. Use Android technical pages for component-oriented investigations (Media3, FFmpeg, libdovi, IEC passthrough).
4. Keep design and operational decisions aligned with documented runtime validation steps.

## Validation and Expected Outcome
- Team members can locate the correct documentation path for each task type
- Architecture discussions map to concrete pages and validation workflows
