# Universal NEXIO Artwork Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Embed a built-in NEXIO artwork provider that can compose premium-style logos, backdrops, thumbnails, and posters inside the Android TV app using already-resolved Nexio artwork and ratings, without requiring external poster APIs and without introducing parallel metadata or artwork paths.

**Architecture:** Add a new internal artwork provider choice that participates in the existing `ArtworkRouter`, `ArtworkDecisionCache`, `ArtworkAssetRepository`, `IntegrationRuntime`, and shared metadata/rating routing. Rendering becomes a local materialization step for selected artwork candidates, not a direct UI fetcher or a separate repository path.

**Tech Stack:** Kotlin, Android Bitmap/Canvas/Paint, Coil existing image loading boundary, DataStore settings, existing metadata routing, existing rating repositories through shared resolver contracts, JUnit/Robolectric/MockK.

---

## Product Framing

Treat this as a local generated artwork provider inside Nexio, not as embedded OpenPosterDB.

Conceptual contract:

```text
Input:
  existing source artwork
  existing resolved ratings
  existing artwork settings

Output:
  locally generated poster / backdrop / logo / thumbnail
  cached through Nexio artwork cache
  rendered by Coil like any other artwork asset
```

This can deliver many of the same user-visible benefits as external premium poster APIs while avoiding extra network calls after the source artwork and ratings are cached.

## Scope

- Support `POSTER`, `LOGO`, `BACKDROP`, and `THUMBNAIL` as first-class artwork types.
- Support title badges:
  - Anime: MAL and IMDb.
  - Movies and TV: IMDb, Rotten Tomatoes, and Metacritic.
- Support episode badges:
  - Non-anime episodes: IMDb.
  - Anime episodes: IMDb and MAL.
- Reuse the artwork Nexio already fetches and caches as the source image.
- Reuse ratings Nexio already resolves, and add missing rating exposure only through shared rating/metadata routing.
- Keep all provider selection, decisions, runtime materialization, and disk caching inside the current artwork system.

## Non-Goals

- Do not integrate OpenPosterDB code directly.
- Do not add an OpenPosterDB server, API, backend dependency, or network requirement.
- Do not call MAL, OMDb, MDBList, IMDb, or any rating repository from the compositor or UI.
- Do not add a dedicated Coil fetcher, direct image URL path, or alternate poster resolver for generated artwork.
- Do not add a second cache for generated artwork outside `ArtworkAssetRepository` and its disk cache.

## Design Summary

OpenPosterDB is useful as a reference for output behavior: take source artwork, normalize rating data, render provider badges, and produce a final image. The NEXIO implementation should port the concept, not the code. The Android app should own a native renderer optimized for TV constraints, fed by existing Nexio metadata and artwork decisions.

The generated provider should look like any other premium artwork provider to the routing layer:

- Settings choose `NEXIO_GENERATED` for any supported artwork type.
- Candidate building creates a generated-artwork candidate only when source artwork and eligible rating badges are available.
- `ArtworkRouter` selects it using the same provider priority and fallback rules.
- `ArtworkAssetRepository` materializes the selected runtime asset.
- The byte loader resolves the source artwork from existing cache/materialization, renders overlays locally, stores the generated bytes in the existing artwork asset cache, and returns the cached URI.

Target flow:

```text
Primary / rail / addon artwork candidate
        ↓
ArtworkRouter selects source artwork candidate
        ↓
Shared rating routing produces normalized badge payload
        ↓
NexioGeneratedArtworkCandidateFactory creates candidate
        ↓
ArtworkRouter may select NEXIO_GENERATED
        ↓
ArtworkAssetRepository materializes generated asset
        ↓
NexioArtworkCompositor renders local bitmap
        ↓
ArtworkAssetDiskCache stores output
        ↓
Coil renders nexio-artwork://asset/{assetKey}
```

## Core Design Decisions

### 1. Provider Identity

Add a new provider choice, tentatively named `NEXIO_GENERATED`.

Modify:

- `app/src/main/java/com/nexio/tv/domain/model/ArtworkProviderSettings.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/ArtworkProviderRegistry.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/ArtworkProviderCapabilityResolver.kt`

Provider properties:

- Supports `POSTER`, `LOGO`, `BACKDROP`, and `THUMBNAIL`.
- Requires no API key.
- Embeds ratings.
- Supports existing ID families only for routing compatibility; it should not use IDs to perform a new provider fetch.
- Is available only when candidate construction can attach:
  - a source artwork reference,
  - a normalized rating badge payload,
  - a render settings hash.

### 2. Rating Badge Contract

Add a renderer-facing contract that is independent of raw provider models.

Create:

- `app/src/main/java/com/nexio/tv/core/artwork/render/ArtworkRatingBadge.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/render/ArtworkRatingBadgeResolver.kt`

Suggested model:

- `source`: `IMDB`, `MAL`, `ROTTEN_TOMATOES`, `METACRITIC`.
- `value`: normalized numeric value.
- `displayText`: already formatted for rendering, such as `8.4`, `87%`, or `72`.
- `scale`: optional scale metadata, such as `OUT_OF_10`, `PERCENT`, `OUT_OF_100`.
- `sourceRatingId`: stable source-specific ID when available.
- `updatedAt` or input data version when available.

Resolution rules:

- Anime title: prefer IMDb plus MAL when both are present; render one badge if only one is present.
- Anime episode: prefer IMDb plus MAL when both are present; render one badge if only one is present.
- Movie/TV title: IMDb, Rotten Tomatoes critic score, and Metacritic when present.
- Non-anime episode: IMDb only.
- Missing ratings should not produce fake or placeholder badges. The router should fall back to the next valid artwork candidate when no eligible badge payload exists.

Important boundary:

`ArtworkRatingBadgeResolver` must consume shared metadata/rating outputs. If current data is only available behind specialized repositories, first expose it through the shared rating routing layer. Do not let the artwork compositor call `MDBListRepository`, `CustomImdbTitleRatingsRepository`, `CustomImdbEpisodeRatingsRepository`, Kitsu services, MAL clients, or OMDb clients directly.

### 3. Metadata Routing Alignment

The provider should depend on the shared metadata routing result, not raw UI models.

Required alignment work:

- Identify the canonical resolved display model used by screens that need artwork.
- Add or extend a shared rating payload on that resolved model for:
  - title ratings,
  - episode ratings,
  - anime-specific ratings,
  - rating provider freshness/version metadata.
- Route existing IMDb movie/TV/episode data into that payload.
- Route existing Rotten Tomatoes and Metacritic data from MDBList-derived models into that payload.
- Route MAL title and episode data into that payload. If MAL episode ratings are not currently represented, add the representation at the shared rating layer before artwork generation.

This keeps the generated provider downstream of the same routing system as every other display surface.

### 4. Candidate Construction

Avoid growing `PosterRatingsUrlResolver` into a large provider-specific renderer coordinator. Add a provider-focused factory and call it from the existing artwork candidate construction point.

Create:

- `app/src/main/java/com/nexio/tv/core/artwork/NexioGeneratedArtworkCandidateFactory.kt`

Responsibilities:

- Receive the canonical content identity, media kind, artwork type, source artwork reference, resolved rating badges, and render settings.
- Build an `ArtworkCandidate` for `ArtworkProvider.NEXIO_GENERATED`.
- Set `sourceRole = PREMIUM`.
- Set `requiresRuntimeFetch = true`.
- Attach a source representation that the existing materialization path can understand.
- Attach `displayHints.embedsRatingOverlay = true`.

Candidate construction should not fetch source bytes or ratings. It only packages already-routed inputs into a candidate.

### 5. Source Representation

Use one of two implementation options, chosen during detailed implementation:

Preferred option:

- Add an explicit generated/local composite source type to `ArtworkSource`, such as `ArtworkSource.LocalComposite`.
- Include:
  - source artwork decision key or asset key,
  - source artwork type,
  - normalized rating badge payload hash,
  - render settings hash,
  - output format,
  - renderer version.

Compatible fallback:

- Reuse `ArtworkSource.ProviderTemplate` with a `NEXIO_GENERATED` provider and structured `pathParams`.
- Include the same fields in `pathParams`.

Either option is acceptable only if it still flows through `ArtworkSourceMaterializer`, `IntegrationRuntime`, and `ArtworkAssetRepository`.

### 6. Materialization and Cache Keys

Modify:

- `app/src/main/java/com/nexio/tv/core/artwork/ArtworkSourceMaterializer.kt`
- `app/src/main/java/com/nexio/tv/core/integration/IntegrationApiShapes.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/ArtworkCacheKeys.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/ArtworkAssetRepository.kt` or its byte-loader collaborator.

Add:

- `ArtworkApiShapes.NEXIO_GENERATED_ARTWORK`.
- Runtime handling for the generated artwork source.
- Local execution metadata:
  - `networkExecuted = false`,
  - cache-first behavior,
  - runtime work classification for user-visible or background hydration work.
- Asset key fields for:
  - provider,
  - artwork type,
  - canonical owner/content ID,
  - source artwork asset key or source image hash,
  - normalized rating badge payload hash,
  - render settings hash,
  - renderer version,
  - routing policy version.

Invalidation rules:

- Source artwork changes -> generated asset key changes.
- Rating values/providers change -> rating badge hash changes.
- Layout/style changes -> renderer version or render settings hash changes.
- Provider settings change -> existing decision settings hash changes.
- Policy changes -> existing policy version changes.

Do not add a separate generated-artwork cache. Generated output should be cached as an artwork asset.

Runtime integration matters even for local generation because it provides single-flight behavior, concurrency limits, playback gating, cache-hit reporting, traceability, and consistent invalidation.

### 7. Renderer

Create:

- `app/src/main/java/com/nexio/tv/core/artwork/render/NexioArtworkCompositor.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/render/ArtworkRenderRequest.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/render/ArtworkBadgeRenderer.kt`
- `app/src/main/java/com/nexio/tv/core/artwork/render/ArtworkRenderSettings.kt`

Renderer behavior:

- Decode source images with bounded dimensions.
- Render into Android `Bitmap` using `Canvas`, `Paint`, and reusable badge/icon assets.
- Produce deterministic output bytes for a given source image, rating payload, settings, and renderer version.
- Use PNG for logos when transparency matters.
- Use JPEG or WebP for posters, backdrops, and thumbnails depending on existing cache conventions.
- Keep badge layout safe for TV overscan and poster grids.
- Constrain memory by downsampling large source art before composition.
- Limit concurrent renders through the same runtime/materialization layer used for artwork fetching.
- Reuse renderer assets and paint objects where safe.
- Write generated output through a temp file plus atomic publish if the current cache writer does not already guarantee this.

Initial output-size targets:

- Poster: 500-780px wide.
- Thumbnail: 640px wide.
- Backdrop: 1280px wide max.
- Logo: preserve transparency and bound max width.

Artwork-type behavior:

- Poster: preserve poster aspect ratio; badges should sit in a stable lower overlay area.
- Thumbnail: preserve episode/video thumbnail aspect ratio; badges should be readable without hiding faces or major scene content where possible.
- Backdrop: use a quieter lower-corner or lower-band treatment suitable for wide images.
- Logo: preserve transparency when source logo supports it; badges should sit outside or beneath the logo composition rather than damaging the logo glyphs.

### 8. Settings and UX

Extend the existing artwork provider settings instead of creating a new settings surface.

Modify:

- existing provider selection UI/state for `POSTER`, `LOGO`, `BACKDROP`, and `THUMBNAIL`.

Behavior:

- `NEXIO_GENERATED` appears as a provider choice for every supported artwork type.
- It should show as local/built-in and not require credentials.
- Existing API-driven providers remain selectable.
- Existing default fallback behavior remains unchanged.
- If generated artwork cannot be produced for a content item, routing falls back to the next candidate.

## Android TV Performance

Cached generated artwork should behave like any cached local image asset. First-time generation is more expensive because the app must decode source artwork, render badges, encode output bytes, and write to disk.

Safe operating constraints:

- Never render on the main thread.
- Limit local generation concurrency to 1-2 jobs.
- Prefer visible, focused, adjacent, or background-hydrated items over whole-row generation.
- Use source artwork already selected by the artwork system.
- Downsample before composition.
- Cache generated output as normal artwork assets.
- Avoid broad generation during playback.
- Serve existing cached generated artwork when available, even if regeneration is queued for fresher inputs.

Risk patterns to avoid:

- Generating every poster in a row at first paint.
- Decoding original 4K artwork for card-sized outputs.
- Encoding PNG for posters/backdrops unless required.
- Re-generating because cache keys are unstable.
- Generating while playback is active without runtime gating.
- Performing rating lookups from the compositor.

Design estimates to validate on low-end Android TV hardware:

| Artwork type | First generation estimate | Notes |
| --- | ---: | --- |
| Episode thumbnail | 10-80 ms | Smaller image, safest early target. |
| Poster | 30-200 ms | Depends on source size, badge count, and encoder. |
| Backdrop | 50-300 ms | Larger bitmap; requires careful downsampling. |
| Logo | 20-150 ms | Transparency and PNG handling may dominate. |
| Cached generated output | normal cached image load | Equivalent to local artwork cache behavior. |

## Implementation Tasks

- [ ] OpenSpec proposal: create a focused change such as `add-universal-nexio-artwork-provider`, document the capability delta, and validate with `openspec validate <change-id> --strict`.
- [ ] Provider model: add `NEXIO_GENERATED` to provider settings, registry, capability checks, provider display metadata, and provider hashing.
- [ ] Shared ratings: define `ArtworkRatingBadge`, implement `ArtworkRatingBadgeResolver`, and connect it to shared metadata/rating routing for IMDb, MAL, Rotten Tomatoes, and Metacritic.
- [ ] Anime ratings: confirm the current MAL title and episode data sources, then expose them through the shared rating payload rather than from the compositor.
- [ ] Candidate factory: add `NexioGeneratedArtworkCandidateFactory` and invoke it from the existing artwork candidate construction flow.
- [ ] Source/materialization: represent generated artwork as a first-class materializable artwork source and map it to a generated artwork API shape.
- [ ] Cache keys: add generated-artwork source hash, rating hash, render settings hash, and renderer version to generated asset keys.
- [ ] Runtime byte loading: implement generated artwork loading through the existing artwork byte loader/materialization path.
- [ ] Renderer: implement native Android bitmap composition for poster, logo, backdrop, and thumbnail outputs.
- [ ] Runtime gating: limit concurrency, avoid playback contention, and make first generation background-safe.
- [ ] Settings UI: add the provider choice to existing artwork provider controls without introducing a separate generated-artwork settings page.
- [ ] Tests: cover provider availability, routing fallback, cache key invalidation, rating badge selection, renderer smoke output, and no-bypass boundaries.
- [ ] Performance validation: verify memory use and render latency on Android TV-class devices or emulator profiles.

## Test Plan

- Unit test `ArtworkProviderRegistry` exposes `NEXIO_GENERATED` for all four artwork types.
- Unit test capability rejection when generated artwork lacks source art or eligible rating badges.
- Unit test rating badge resolution:
  - anime title with MAL and IMDb,
  - anime episode with MAL and IMDb,
  - movie title with IMDb, Rotten Tomatoes, and Metacritic,
  - non-anime episode with IMDb,
  - missing ratings produce no generated candidate.
- Unit test generated cache keys change when source hash, rating values, render settings, or renderer version change.
- Router test confirms generated candidates are selected only through `ArtworkRouter` and fall back cleanly.
- Repository/materialization test confirms generated bytes are written through the existing artwork asset cache.
- Robolectric renderer smoke tests confirm non-empty images for poster, logo, backdrop, and thumbnail requests.
- Architecture test or targeted code review checklist confirms no UI or compositor code calls rating repositories or external provider clients directly.

## Benchmark Acceptance

Before broad rollout, run a benchmark matrix across:

- Poster at 500px and 780px wide.
- Thumbnail at 640px wide.
- Backdrop at 1280px wide.
- One, two, and three badges.
- Cold source asset vs cached source asset.
- Low-end Android TV hardware or emulator profile vs development device.

Capture:

- decode time,
- render time,
- encode time,
- total time,
- peak memory,
- output file size,
- frame drops or visible jank.

Initial targets:

- Cached generated output should load like normal cached artwork.
- First poster generation should be under roughly 250 ms on low-end Android TV hardware.
- First thumbnail generation should be under roughly 100 ms.
- All generation must remain off the main thread.
- No visible frame drops during navigation or playback.

If target devices miss these numbers, generated artwork should be focused/idle/background only: show normal artwork first, then swap in generated artwork when ready.

## Rollout Strategy

- Ship behind the existing artwork provider selection setting; no global automatic replacement at first.
- Sequence after the unified artwork cache path, `ArtworkDisplayRef` migration, and premium provider routing correctness are stable enough for generated artwork to plug in cleanly.
- Phase 1: posters with title-level ratings.
- Phase 2: episode thumbnails with episode-level ratings.
- Phase 3: backdrops and logos after visual layout rules are proven.
- Use renderer versioning from day one so visual changes invalidate cached generated assets cleanly.
- Log routing traces for generated candidates using the existing `ArtworkDecisionTrace` structure.
- Monitor cache growth and render failures through existing artwork cache/runtime diagnostics.

## Product And Policy Review

This could become a supporter feature, but monetization needs separate product/legal review before implementation decisions are locked.

Review items:

- Google Play Billing requirements for any Play-distributed paid unlock.
- Whether Patreon or external supporter unlocks are allowed for each distribution channel.
- Trademark and data-use constraints for IMDb, Rotten Tomatoes, Metacritic, and MAL names/logos.
- Whether generated rating badge assets need alternate unbranded visual treatments.

## Open Questions

- MAL episode ratings must be confirmed in the current Nexio data model. If they are not already available, the first implementation task is adding them to shared rating routing.
- Decide final naming: `NEXIO_GENERATED`, `NEXIO_ARTWORK`, or `NEXIO_PREMIUM`. The name should make clear this is built-in and local, not a remote API.
- Decide whether generated source representation should be a new `ArtworkSource.LocalComposite` or a constrained `ProviderTemplate` shape. The former is clearer; the latter may be less invasive.
- Decide final output format per artwork type based on current disk cache and image pipeline expectations.

## Self-Review

- Logo, backdrop, thumbnail, and poster support is represented as provider capability, candidate construction, renderer behavior, and tests.
- MAL and IMDb anime support is handled by a shared rating badge resolver, with MAL episode availability called out as a concrete dependency.
- IMDb, Rotten Tomatoes, and Metacritic movie/TV support is handled through the same rating badge resolver.
- IMDb episode support reuses the existing built-in episode rating path by routing it into the shared rating payload.
- The design uses `ArtworkRouter`, `ArtworkDecisionCache`, `ArtworkAssetRepository`, `ArtworkSourceMaterializer`, and `IntegrationRuntime`; it does not add a parallel artwork pipeline.
- Generated assets are invalidated by existing decision settings plus source, rating, render settings, renderer version, and policy hashes.
- Android TV performance is addressed through background materialization, bounded output sizes, concurrency limits, and a benchmark gate.
- External API-driven providers remain independent choices and fallback candidates.
